
# Differentiable Rigid Solver Engine

다시, 현재 sweeptable은 blackbox engine 을 역산할 수 있도록 inverse dynamics 표표를 만든 것이고, 현재는 그 engine 방정식이 제공되기에, 이를 미분 기반반으로 역산하려해.

  우리가 비교하고싶은 것은 1. openloop 기준 sweeptable vs differentiable engine 의 경로 비교.
  2. sweeptable + stanley vs differentiable engine + stanley 임.
---

### SDK 1.3.0 DifferentiablePlant vs SweepTable (2026-08-20)

Base Stanley 의 역플랜트(목표 a·ω → T·S)만 교체, RL_STN 잔차·나머지 스택 동일. 단일 env 하네스(`9_obstacle.py --headless`, `STANLEY_PLANT=diff`).

| 구분 | SweepTable (v2 표, 채택) | DifferentiablePlant (SDK 1.3.0) |
|---|---|---|
| 원리 | 개루프 측정 5D 표 역조회 | SDK 힘 모델 autograd 야코비안 + Newton 역산 (horizon 4스텝) |
| 개루프 예측 (p302/p161, 4스텝 truth) | a RMS 2.9 / ω RMS 0.35~0.48 | a RMS 0.11~0.40 / ω RMS 0.002~0.008 |
| 개루프 예측 (2 s truth) | a 2.5~4.8 / ω 0.32~0.37 | a 1.7~3.9 / ω 0.15~0.48 |
| 개루프 경로 (참조 a·ω 스케줄 역산 주입, 위치 피드백 없음) p120 / p343 | 편차 평균 **0.28 / 4.9 m**, v 오차 −0.3 / −0.7 (+g·sin 보정 시 0.16 / 23 m, v −2.0 / −2.1) | 편차 평균 1.8 / 37.7 m, v 오차 +1.9 / +2.6 (과가속) |
| 폐루프 16씬 완주 | 15/16 (p145 실패) | 16/16 |
| 폐루프 \|CTE\| 평균 (cm) | **8.8** | 22.0 (경사 p166 99·p169 137 제외 시 8.9) |
| 폐루프 v 오차 평균 (m/s) | **0.47** | 0.86 |
| 스텝 비용 (하네스 전체, ms) | 45 | 142 (+~90 ms/스텝, 단일 차량·CPU autograd) |

결론: **스윕 테이블 유지.** 평지·완경사(T3k 포함)에선 동급(차이 ±2 cm), 경사 씬(p166/p169)에서 DifferentiablePlant 가 발산 — 플랜트가 라이브 자세로 g·sinθ 를 모델링하지만 실제 SDK 레이휠은 경사에서 중력의 경사방향 성분이 작용하지 않기 때문(`core.py _up_world=(0,0,1)` 상수, 아래). 비용도 3배라 512 env 학습 루프엔 부적합.

**발견 — SDK 경사 중력 미작용 (버그)**: 15° 기울인 평판에서 브레이크를 놓아도 3 s 동안 이동 3 mm(`z_tmp_p2/plant/_tilt_box.py`), T3k 2.3%·p00 11° 경사 코스팅 속도 일정(`_coast.py`). 서스펜션 N 이 항상 월드 연직으로 가해져 mg 를 전부 상쇄. 스윕표(중력 회전 측정)·DifferentiablePlant 는 둘 다 g·sinθ 를 가정 → 경사에서 실제와 불일치. Stanley 의 `+g·sin(pitch)` 보정·reparam 의 "내리막 감속 불가" 가정은 존재하지 않는 효과를 보정 중(RL_STN 이 흡수). SDK 보고/수정 여부 미결.
