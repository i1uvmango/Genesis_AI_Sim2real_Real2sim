# STORM Feed-forward Training Plan on Alpamayo

> 공개된 STORM의 구조와 가중치, 여러 카메라를 쓸 수 있는지 확인한 결과를 정리하고, 우리 카메라 배치와 경로 밖 시점에 맞게 STORM을 추가 학습하기 위한 연구 지점, 데이터셋 제작 방법, 학습 계획을 기록함

## 용어

| 용어 | 설명 |
|---|---|
| feed-forward | 씬마다 수만 번 최적화하지 않고, 미리 학습된 신경망을 한 번 통과시켜 Gaussian을 얻는 방식 |
| 장면별 학습 | 한 장면의 Gaussian 값 자체를 그 장면 사진으로 반복 최적화하는 방식. 우리 v4 학습이 여기에 해당함 |
| STORM | NVIDIA 등이 ICLR 2025에 발표한 feed-forward 모델. 카메라 3대와 시점 4개의 사진 12장으로 2초 구간의 Gaussian과 속도를 한 번에 냄 |
| prior | 다른 데이터로 미리 학습해 둔 신경망 가중치. 처음 보는 장면에서도 거리와 움직임을 짐작하는 능력이 여기에 들어 있음 |
| fine-tune | 공개 가중치에서 시작해 우리 데이터로 추가 학습하는 것 |
| 토큰 | Transformer가 다루는 단위. STORM은 사진의 8x8 화소 조각 하나를 768차원 토큰 하나로 바꿈 |
| Plücker 좌표 | 화소가 3차원의 어느 광선 위에 있는지를 숫자 6개로 적은 것. 광선 방향과 모멘트로 이뤄짐. 깊이 정보는 아님 |
| 노출 토큰 | STORM이 카메라마다 하나씩 두는 특수 토큰. 카메라별 밝기와 색감 차이를 색 변환으로 흡수함. 공개 가중치에는 3개만 있음 |
| 움직임 토큰 | 각자 속도 하나를 대표하는 특수 토큰 16개. 화소마다 어느 토큰에 속하는지 가중치를 내고 그 가중 평균이 속도가 됨 |
| 채점 시점 | 학습 때 손실을 계산하는 정답 사진의 시점 |
| 경로 위 시점, 경로 밖 시점 | 기록 차량이 실제로 지나간 곳의 카메라 시점과, 옆 차로처럼 지나가지 않은 곳의 시점 |
| 뺀 카메라 평가 | 일부 카메라를 입력에서 빼고, 그 카메라 사진을 정답으로 처음 보는 시점 품질을 재는 방법 |
| Difix | 렌더의 흐림과 구멍을 한 번에 고치는 diffusion 모델. 쌍 데이터(흐린 렌더와 정답 사진)로 학습함 |
| PhysicalAI-AV | 알파마요 데이터의 원본 공개 데이터셋. 20초 조각, 카메라 7대, LiDAR |
| v4 | 알파마요 058 장면별 학습 결과. 이미 학습된 v3 맵에서 시작해 45000회 학습함 |
| v4_storminit, v4_lidarinit | v4와 같은 학습 방식인데 시작점만 STORM 출력 Gaussian 또는 색을 입힌 LiDAR 점으로 바꾼 것 |
| PSNR, SSIM, LPIPS | 렌더와 실제 사진의 차이를 재는 값. PSNR과 SSIM은 높을수록, LPIPS는 낮을수록 좋음 |

## 요약

**결과**

- 공개 STORM 가중치는 STORM 1저자가 다시 학습해 올린 비공식 재현본임. 카메라 3대, 240x160, 2초 구간, LiDAR 깊이 손실을 켜고 A100 16장으로 약 24시간 학습한 것임
- 공개 가중치를 알파마요 058에 그대로 쓰면 2초 구간 하나를 160 ms에 만들지만 PSNR은 17.8로 장면별 학습 22.6보다 크게 낮음. 깊이는 LiDAR보다 1.4배 멀게 나옴
- Waymo 5대 카메라로 학습된 STORM 가중치는 공개된 것이 없음. 코드와 구조는 카메라 수를 늘릴 수 있고, 카메라 수에 묶인 부분은 노출 토큰뿐임
- STORM은 학습 때 같은 카메라의 다른 시각으로만 채점받음. 경로 위 시점으로만 훈련받았고 옆으로 옮긴 시점은 학습한 적이 없음. 연구 지점은 여기에 둠
- 학습 계획은 알파마요 조각으로 우리 카메라 배치에 맞추는 fine-tune에서 시작해, 뺀 카메라 채점으로 경로 밖 시점 신호를 넣고, 마지막에 렌더 보정기와 묶는 순서로 잡음

**미해결**

- 4090 한 대에서 1회 학습 시간과 메모리를 아직 재지 않았음. 아래 학습 시간은 모두 원래 학습량에서 비율로 계산한 추정임
- 5대 카메라 무학습 시험을 아직 하지 않았음
- PhysicalAI-AV에서 같은 장소를 다른 차로로 지나간 조각이 있는지 확인하지 않았음
- feed-forward 모델에 경로 밖 채점과 렌더 보정 고리를 묶은 선행 연구가 있는지 깊게 조사하지 않았음

## 1. STORM 구조와 가중치

### 1.1 구조

| 순서 | 하는 일 | 우리 설정에서의 크기 |
|---|---|---|
| 입력 | 카메라 3대(좌, 정면, 우)와 시점 4개의 사진, 각 사진의 카메라 포즈와 시각 | 240x160 사진 12장, 2초 구간 |
| 광선 붙이기 | 화소마다 색 3개 옆에 Plücker 좌표 6개를 붙임. 어느 광선 위인지만 알려 주고 깊이는 아직 모름 | 화소당 값 9개 |
| 토큰화 | 8x8 조각마다 값 576개를 선형층으로 768차원 토큰 하나로 바꾸고, 조각 위치와 시각 정보를 더함 | 장당 600개, 합계 7200개 |
| 특수 토큰 | 하늘 1개, 노출 3개, 움직임 16개를 앞에 붙임 | 합계 7220개 |
| Transformer | ViT-Base 12층. 모든 토큰이 서로 attention을 계산하며 다른 시점과 다른 카메라 사진에서 같은 물체를 찾아 거리와 움직임을 알아냄 | 계산의 대부분 |
| 화소로 풀기 | 토큰을 다시 화소 단위로 풀어 화소마다 깊이, 크기, 회전, 불투명도, 색, 속도를 냄 | 화소당 Gaussian 1개, 합계 460800개 |
| 위치 | 카메라 위치에 깊이와 광선 방향을 곱한 값을 더한 곳. 시각이 바뀌면 속도와 시간 차를 곱한 만큼 이동함 | |

| 부분 | 파라미터 |
|---|---|
| 백본 Transformer (12층, 768차원, attention head 12개, MLP 3072) | 85.05 M (85%) |
| 움직임 head | 10.08 M |
| Gaussian head | 2.82 M |
| 토큰화, 위치와 시각 embedding | 1.69 M |
| 하늘과 노출 head | 0.93 M |
| 합계 | 100.6 M |

**백본은 이미지 분류용 표준 ViT-Base와 같은 크기임. 4090 한 대로 fine-tune을 시도할 만한 크기로 판단함**

- VGGT와 DGGT는 약 10억 개급이라 STORM보다 약 10배 큼
- 2초로 끊는 이유는 두 가지임. 학습을 2초 조각으로만 했고, 구간을 늘리면 attention 계산이 토큰 수의 제곱으로 늘어남. 같은 촘촘함으로 20초를 넣으면 계산량이 약 65배로 추정됨

### 1.2 공개 가중치의 학습 조건

| 항목 | 값 |
|---|---|
| 만든 사람 | STORM 1저자. NVIDIA 공식이 아닌 비공식 재현본으로 GitHub issue에 공개함 |
| 데이터 | Waymo Open Dataset, 학습 장면 798개, 검증 장면 202개 |
| 카메라 | 앞쪽 3대 (앞왼쪽, 정면, 앞오른쪽) |
| 입력 | 240x160 사진 12장, 2초 구간 |
| 채점 | 같은 2초 안에서 무작위로 고른 시각 4개의 같은 카메라 사진 |
| 손실 | 색 손실, 지각 손실(LPIPS, 5000회 이후), LiDAR 깊이 손실, 하늘 불투명도 손실, 속도 규제 |
| 학습량 | 100000회, 실효 배치 64, A100 16장으로 약 24시간 (약 384 GPU 시간) |

### 1.3 공개 가중치를 알파마요 058에 그대로 쓴 결과

| 방법 | 학습 | 시간 | PSNR | 메모 |
|---|---|---|---|---|
| STORM 단독 | 없음 | 2초 구간당 160 ms | 17.8 | 2초마다 끊김, 번짐, 깊이 1.4배 멂 |
| v4_storminit | STORM 출력에서 시작해 45000회 | 약 1.3 h | 22.30 | 버스 같은 큰 물체 형태를 더 일찍 잡음 |
| v4_lidarinit | LiDAR 점에서 시작해 45000회 | 약 1.3 h | 22.19 | |
| v4 | v3 맵에서 시작해 45000회 | v3 포함 약 4.1 h | 22.55 | |

**속도는 충분하지만 품질과 깊이 단위가 맞지 않음. 한계는 모두 1.2절의 학습 조건에서 나옴**

- 깊이 1.4배 오차는 Waymo 카메라 화각과 높이에 맞춰 거리 감각을 배웠기 때문으로 추정함
- PSNR은 정면 카메라 199장 기준이고 학습에 쓴 사진으로 잰 값임. 경로 밖 시점 품질은 아직 잰 수치가 없음
- 비교 영상은 `../../res_wjdaksry/1127/` 에 있음

## 2. 여러 카메라 확인 결과

### 2.1 사방 카메라 prior가 있는가

| 모델 | 카메라 | 공개 가중치 | 비고 |
|---|---|---|---|
| STORM | 앞쪽 3대 | 있음 (비공식) | 움직임 있음 |
| STORM 5대 배치 | Waymo 5대 | **없음** | 코드는 지원함. 학습하면 만들 수 있음 |
| DrivingForward (AAAI 2025) | nuScenes 사방 6대 | 있음 | 구조가 다르고 데이터가 nuScenes |
| VGGT, DGGT | 장수 제한 없음 | 있음 | 실제 거리 단위 없음 |

- GitHub issue 19개, 논문 페이지, HuggingFace를 확인한 결과임

### 2.2 STORM에 카메라를 더 넣을 수 있는가

**구조상 가능함. 카메라 수에 묶인 것은 노출 토큰 3개뿐임**

- Transformer는 토큰 수에 제한이 없고, 조각 위치 embedding(600개)은 모든 사진이 같이 씀
- 5대를 넣으려면 노출 토큰을 5개로 늘려야 함. 학습 없이 넣으려면 기존 토큰을 복사해야 함
- 우리 원본 알파마요에는 카메라가 7대 있음(정면 광각 120도, 정면 망원 30도, 좌우 120도, 좌후와 우후 70도, 후방 망원 30도). 지금 처리한 것은 그중 5대를 90도 핀홀로 편 것이고, 사방을 다 덮을 수 있음
- 지금 3대 입력이 덮는 범위는 정면 기준 좌우 약 74도까지임. 차 바로 옆과 뒤는 Gaussian이 없음

| 방법 | 학습 | 예상 |
|---|---|---|
| 묶음별로 따로 돌려 합치기 (앞 묶음과 뒤 묶음) | 없음 | 구간당 약 0.32 s. 묶음 경계가 두 겹으로 겹칠 수 있음 |
| 5대를 한 번에 넣기 (노출 토큰 복사) | 없음 | 토큰 12000개, 약 0.4 s 추정. 처음 보는 배치라 품질 확인이 필요함 |
| 우리 배치로 fine-tune | 필요 | 5절 학습 계획 |

- 사방을 넣으면 안 본 방향의 빈 곳은 사라짐. 가려진 곳(주차된 차 뒤, 건물 뒤)은 어느 카메라로도 안 보였으므로 그대로 남음

## 3. 연구 지점

| 순위 | 연구 지점 | 주장할 수 있는 것 | 근거 |
|---|---|---|---|
| 1 | 경로 밖 시점 학습 신호 | 다른 카메라와 옆 시점 정답으로 feed-forward 모델을 학습시켜 차로 변경 시점 품질을 올림 | STORM이 경로 위 시점으로만 학습됨. 왼쪽 3 m 시점에서 번짐 |
| 2 | 회귀 모델과 렌더 보정기 결합 | STORM으로 빠르게 형상을 만들고, 보정기로 빈 곳을 채운 그림을 가짜 사진으로 STORM에 다시 넣는 고리. 시뮬레이터에서 사진 없이 포즈만 있는 입력 불일치를 해결함 | 화소당 Gaussian 하나라 안 본 곳을 못 채움 |
| 3 | 사방 카메라, 임의 카메라 배치 | 우리 7대 배치에서 360도 feed-forward 생성 | 공개된 사방 STORM이 없음 |
| 4 | LiDAR 입력 조건 | 깊이 1.4배 오차를 없앰 | 실측 오차 있음 |
| 5 | 긴 구간 일관성 | 2초 끊김을 없앰 | 실측 끊김 있음 |

**1번과 2번을 묶은 "시뮬레이터용 경로 밖 feed-forward 장면 생성"을 주제로 잡음**

- 3번과 4번은 도메인 적응 성격이라 연구 기여로는 약함. 다만 1번과 2번의 전제 조건임
- 5번은 이전 구간 정보를 넘겨받는 구조를 새로 학습해야 해서 뒤로 미룸

## 4. 데이터셋 제작 방법

### 4.1 STORM fine-tune용 조각

| 단계 | 내용 |
|---|---|
| 원본 | PhysicalAI-AV. 미국, 낮 9시에서 16시, 카메라 5대와 LiDAR가 모두 있는 조건을 만족하는 조각이 67639개임. 그중 시범으로 학습 50개, 검증 5개를 무작위로 고름. 조각 하나를 받는 양은 카메라 5대와 LiDAR를 합쳐 약 440 MB이고 약 70초 걸림 (실측) |
| 변환 결과 | 조각 하나에 약 150 MB에서 190 MB (사진 약 45 MB, 0.1 m 간격으로 솎은 LiDAR 약 110 MB). 변환은 조각당 약 80초 (실측). 변환 뒤 원본은 지움 |
| 사진 | 광각 카메라를 90도 핀홀 조각 여러 장으로 펴서 사방을 덮고 240x160으로 줄임 |
| 포즈와 시각 | 차 궤적과 카메라 장착 위치로 카메라 포즈를 만들고, 구간 안 시각을 0에서 1로 정규화함 |
| LiDAR 깊이 | deskew한 LiDAR 점을 각 사진에 투영한 깊이 지도. 깊이 손실 정답으로만 씀 |
| 하늘 마스크 | SAM3로 만듦. 하늘 Gaussian은 쓰지 않는 기존 규칙에 맞춰 하늘 화소는 불투명도 0으로 학습함 |
| 형식 | STORM의 장면별 json 형식으로 변환하고, 조각 단위로 학습과 검증을 나눔 |

- 058 처리에서 만든 파이프라인(카메라 펴기, 포즈, deskew LiDAR, SAM3 하늘 마스크)을 조각 여러 개에 그대로 돌리는 작업임

### 4.2 채점 정답 설계

Difix3D+가 쌍 데이터를 만든 방법(성긴 재구성, 순환 재구성, 교차 참조, 덜 학습시키기)을 STORM 채점 정답 설계에 빌려 옴.

| 정답 종류 | 만드는 법 | 본뜬 Difix3D+ 방법 | 신뢰도 |
|---|---|---|---|
| 같은 카메라 다른 시각 | 지금 STORM 방식 그대로 | 없음 | 실제 사진 |
| 다른 카메라 | 일부 카메라만 입력하고 뺀 카메라(예를 들어 좌우)로 채점 | 교차 참조 | 실제 사진 |
| 옆으로 옮긴 시점 | LiDAR로 잡은 장면별 재구성에서 1 m에서 3 m 옆 시점을 렌더해 낮은 가중치로 씀 | 순환 재구성 | 가짜 정답이라 낮음 |
| 다른 차로 주행 | 같은 장소를 다른 차로로 지나간 다른 조각 | 없음 | 실제 사진. 있는지 확인 필요 |

**다른 카메라 채점이 가장 싸고 확실한 경로 밖 신호임**

- 실제 사진이라 가짜 정답의 오류가 섞이지 않음
- 카메라 사이 위치 차이는 1 m 안팎이고 방향 차이가 커서, 옆 차로 3 m 이동을 완전히 대신하지는 못함

### 4.3 렌더 보정기용 쌍 데이터

| 항목 | 내용 |
|---|---|
| 입력 | 뺀 카메라 위치에서 STORM으로 렌더한 그림. 흐림과 빈 곳이 자연스럽게 생김 |
| 정답 | 같은 위치의 실제 사진 |
| 규모 예시 | 300조각에서 프레임 200장, 뺀 카메라 2대를 쓰면 약 12만 쌍 |
| 참고 규모 | FlowR(ICCV 2025)는 재구성 장면 10.3k개에서 3.6M 쌍을 씀 |

- STORM 자체가 쌍 생성기 역할을 하므로 장면별 재구성을 따로 돌리지 않아도 됨

## 5. 학습 계획

### 5.1 단계

| 단계 | 기간 추정 | 할 일 | 넘어가는 기준 |
|---|---|---|---|
| 평가 기준과 무학습 시험 | 2일 | 뺀 카메라 PSNR, SSIM, LPIPS 평가를 만들고 STORM, DGGT, v4, v4_storminit 기준선을 잼. 2.2절의 5대 카메라 무학습 시험 두 가지. 4090에서 1회 학습 시간과 메모리 측정 | 기준선 수치 확보 |
| 데이터 파이프라인 | 1주 | 시범 50조각 다운로드와 변환, 공개 가중치로 평가가 돌아가는지 검증 | 50조각이 학습 입력으로 읽힘 |
| 도메인 적응 | 학습 1일에서 2일 | 카메라 3대 설정 그대로 알파마요로 fine-tune. 약 2만 회, 배치 8을 gradient 누적으로 맞춤 | 깊이 단위 오차와 뺀 카메라 PSNR이 기준선보다 좋아짐 |
| 사방 카메라 | 학습 3일에서 4일 | 노출 토큰을 카메라 수만큼 늘려 사방 배치로 학습 | 옆과 뒤의 빈 곳이 사라짐 |
| 경로 밖 채점 | 1주 | 다른 카메라 채점을 추가하고, 옆 시점 가짜 정답은 낮은 가중치로 넣음 | 뺀 카메라와 3 m 옆 시점 품질 향상 |
| 렌더 보정기와 고리 | 2주 | STORM 렌더와 정답 쌍으로 Difix를 fine-tune하고, 렌더 보정 뒤 STORM에 다시 넣는 고리를 시험 | 경로 밖 빈 곳이 채워지고 수치가 유지됨 |
| 정리 | 1주에서 2주 | 비교 실험, 속도 측정, 논문 초안 | |
