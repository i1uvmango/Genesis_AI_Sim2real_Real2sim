# Street View Photos as Extra Training Views for the ADI Scene

> 네이버 거리뷰 사진을 ADI scene 학습에 추가 시점으로 넣는 파이프라인 계획. 네이버 클라우드의 저장 및 학습 사용 동의를 받았다는 가정으로 씀. 2026-11-12 기준, 아직 실행하지 않은 계획임

## 용어

| 용어 | 설명 |
|---|---|
| ADI | 직접 촬영한 주행 데이터. 360 카메라를 4방향 가상 카메라(1440 by 540)로 잘라 쓰고, VLP-16 LiDAR가 있음. 2019년 11월 촬영 |
| 거리뷰 파노라마 | 네이버 지도의 거리 파노라마. 지점마다 파노라마 ID, 좌표, 촬영일이 있음 |
| Naver Maps JavaScript API v3 Panorama | 브라우저에서 파노라마를 띄우는 공식 뷰어. 위치, 화면 크기, 보는 방향(pan, tilt, fov)을 코드로 지정함 |
| Dynamic Map | 네이버 클라우드 Maps의 웹 지도 상품. 파노라마 뷰어도 이 키로 띄움 |
| 대표 계정 | 무료 이용량을 받는 계정. 휴대폰 번호당 Maps를 처음 쓴 계정 1개 |
| mesh-bound 2DGS | Gaussian을 mesh 면 위에 고정하고 사진 색만 학습하는 우리 scene 표현 |
| 추가 시점 입력 | 학습에 원래 카메라 외의 사진을 더 넣는 기능. 이름, 카메라 자세, 이미지, 마스크, 손실 가중치로 구성. 지금은 Difix 가상 시점을 넣는 데 씀 |
| LightGlue | 두 사진 사이 특징점을 짝짓는 학습 기반 매칭 모델. SuperPoint 특징점과 같이 씀 |
| Perspective-n-Point (PnP) | 사진 픽셀과 3D 점의 짝으로 카메라 자세를 푸는 방법. RANSAC으로 틀린 짝을 걸러냄 |
| 재투영 오차 | 풀린 자세로 3D 점을 사진에 다시 찍었을 때 실제 픽셀과의 거리. 정합 품질 지표 |
| holdout PSNR | 학습에서 뺀 ADI 사진으로 잰 화질 지표. 블록 80 인도 LiDAR scene 기준 18.70 |
| 궤적 밖 시점 | ADI 카메라가 지나가지 않은 시점. Genesis 추적 카메라가 여기에 해당함 |

## 요약

**결과**

* 수집 수단은 확인됨. 공식 파노라마 뷰어가 위치와 방향을 코드로 받고, 파노라마 ID, 좌표, 촬영일을 돌려줌
* 비용은 무료 범위 안임. Dynamic Map 무료 이용량은 대표 계정당 월 6,000,000건이고 콘솔 한도를 월 5,900,000건, 일 200,000건, 초과 사용 금지로 걸었음. 경로 전체 수집도 수천 건 수준임
* 매칭 모델은 설치하고 ADI 사진으로 시험했음. LightGlue로 2프레임 떨어진 사진끼리 대응점 977개, 20프레임 떨어진 사진끼리 328개, 한 쌍에 0.02초
* 자세 정합은 사람 손 없이 코드로 돌릴 수 있음. LiDAR mesh가 픽셀마다 깊이를 주므로 매칭만 되면 PnP로 자세가 나옴

**미해결**

* 네이버 동의를 아직 받지 않았음. 동의 전에는 거리뷰 화면을 저장하지 않음
* 거리뷰 사진으로 정합을 한 번도 돌리지 않아 성공률을 모름. 시기 차이 7년, 렌즈 차이, 우리 렌더의 흐림이 매칭을 떨어뜨릴 수 있음
* 거리뷰 촬영 카메라 높이는 약 2.5 m로 알고 있으나 확인하지 않았음
* **판단 필요** 원본 제공을 요청할지, 뷰어 캡처 허용만 받을지

## 1. 전체 흐름

| 단계 | 입력 | 출력 | 자동 여부 |
|---|---|---|---|
| 1. 수집 | ADI 경로 좌표 | 지점별 사진 8장과 메타데이터 | 자동 |
| 2. 초기 자세 | 파노라마 좌표, 방향, 정밀도로지도 높이 | scene 좌표의 대략적 자세 | 자동 |
| 3. 정밀 정합 | 초기 자세, mesh, 사진 | 사진별 정확한 자세 또는 폐기 | 자동, 표본만 눈으로 확인 |
| 4. 마스크 | 사진 | 학습 제외 영역 | 자동, 표본만 눈으로 확인 |
| 5. 색 맞춤 | 사진, 같은 곳의 ADI 렌더 | 색 보정된 사진 | 자동 |
| 6. 학습 | 보정 사진, 자세, 마스크 | 거리뷰를 더한 scene | 자동 |
| 7. 평가 | ADI holdout, 거리뷰 시험 지점 | 화질 비교표 | 자동 |

**정밀 정합이 병목임** 여기서 성공률이 낮으면 뒤 단계가 모두 의미가 없으므로 블록 80 하나로 정합부터 검증함

## 2. 수집

| 항목 | 내용 |
|---|---|
| 방식 | 원본 제공을 받으면 그대로 씀. 뷰어 캡처만 허용되면 로컬 페이지를 자동 브라우저로 열고 지점과 방향을 바꿔 가며 화면을 저장함 |
| 지점 | ADI 경로를 따라 약 10 m 간격의 모든 파노라마. 반대 차로와 교차로 옆길 파노라마도 포함 |
| 방향 | 화각 90도로 수평 4방향, 위로 30도 기울여 4방향. 지점당 8장 |
| 해상도 | 화면 크기를 1440 by 1440 이상으로 지정함. ADI 사진과 비슷한 픽셀 밀도를 맞추기 위함 |
| 시기 | 과거 촬영분을 고를 수 있으면 2019년 11월에 가장 가까운 것 |
| 기록 | 사진마다 파노라마 ID, 좌표, pan, tilt, fov, 촬영일, 저장 시각 |
| 화면 정리 | 캡처 방식이면 뷰어 위 버튼과 로고를 숨기거나 마스크로 뺌 |

* 위쪽 사진은 ADI 카메라가 못 본 건물 상층과 하늘을 채우는 용도임
* 사진은 뷰어가 다음 지점으로 넘어가 화면이 다 그려진 뒤에 저장함. 지점 변경 완료 이벤트 후 일정 시간 대기
* 키 값은 실행할 때만 넘기고 로그, 파일, 커밋에 남기지 않음

## 3. 초기 자세

| 값 | 구하는 법 | 예상 오차 |
|---|---|---|
| 수평 위치 | 파노라마 좌표를 기존 OSM 정렬값으로 scene 좌표로 옮김 | 수 m (GPS 오차) |
| 높이 | 그 위치의 정밀도로지도 노면 높이에 카메라 높이를 더함 | 0.3 m 안팎 |
| 방향 | 뷰어에 지정한 pan, tilt를 그대로 씀 | 파노라마 북쪽 기준 오차만큼 |
| 내부 파라미터 | 화각 90도와 화면 크기로 계산 | 캡처 방식이면 정확함 |

* 정밀도로지도 높이는 위치별 보정(반경 30 m)을 켠 값을 씀. 경로가 길면 단일 보정값으로는 바닥이 최대 0.78 m 뜸

## 4. 정밀 정합

**핵심 아이디어** 초기 자세에서 우리 scene을 렌더하면 픽셀마다 mesh 깊이가 나옴. 거리뷰 사진과 그 렌더를 매칭하면 사진 픽셀과 3D 점의 짝이 자동으로 생기고, PnP가 자세를 풂

| 순서 | 내용 |
|---|---|
| 1 | 초기 자세에서 scene 색 렌더와 깊이 렌더를 만듦 |
| 2 | LightGlue로 거리뷰 사진과 색 렌더의 대응점을 찾음 |
| 3 | 렌더 쪽 대응점에 깊이를 붙여 3D 점으로 바꿈. 깊이 5 m 미만과 하늘 픽셀은 버림 |
| 4 | PnP와 RANSAC으로 자세를 풂 |
| 5 | 풀린 자세에서 다시 렌더하고 1번부터 한 번 더 반복함. 초기 오차가 커서 첫 매칭이 적을 때를 위함 |
| 6 | 한 파노라마에서 나온 8장은 같은 위치를 공유하도록 묶어서 최종 자세를 정함 |

| 합격 기준 | 값 |
|---|---|
| RANSAC 통과 대응점 | 100개 이상 |
| 재투영 오차 중앙값 | 2 px 이하 |
| 초기 자세에서 이동 거리 | 5 m 이내 |
| 같은 파노라마 8장끼리 위치 차이 | 0.3 m 이내 |

* 렌더가 흐려 매칭이 적으면 대안으로 가장 가까운 ADI 실사진과 매칭하고 깊이만 mesh에서 가져옴. ADI 사진은 자세를 알고 있으므로 같은 방식으로 3D 점이 생김
* 매칭에는 건물 외곽, 차선, 연석처럼 안 바뀌는 구조물이 많이 잡혀야 함. 간판과 가로수는 7년 사이 바뀌었을 수 있어 틀린 짝의 원인이 됨
* LiDAR가 없는 테헤란로 구간은 깊이를 V-World 건물 상자와 정밀도로지도 노면에서만 얻으므로 정합 정확도가 낮을 것으로 예상함

#### 승인 전 사전 시험

| 항목 | 내용 |
|---|---|
| 방법 | ADI 프레임 하나를 학습에서 빼고 정답 자세를 3 m, 5도 틀어 놓은 뒤 정합 코드가 되돌리는지 봄 |
| 판정 | 위치 오차 0.3 m, 방향 오차 1도 이내로 복원 |
| 한계 | 같은 카메라, 같은 날 사진이라 거리뷰보다 쉬움. 통과해도 거리뷰 성공은 보장되지 않고, 실패하면 방법을 바꿔야 한다는 것만 확실해짐 |

## 5. 마스크

| 제외 대상 | 방법 |
|---|---|
| 차량, 보행자, 자전거 | SAM3 텍스트 프롬프트 |
| 거리뷰 촬영 차량과 그림자 | 아래쪽 tilt 사진에서 SAM3, 또는 화면 하단 고정 영역 |
| 얼굴과 번호판 블러 영역 | SAM3 결과를 넓혀서 함께 뺌 |
| 파노라마 이음매 근처 | 깊이 5 m 미만 픽셀 제외로 대부분 처리됨. 가까운 물체가 이음매에서 어긋나기 때문 |
| 계절이 다른 나무 | 촬영 월이 ADI와 다르면 식생 영역 전체를 뺌 |
| 뷰어 화면 표시물 | 캡처 방식일 때만. 고정 위치라 한 번 만든 마스크를 재사용 |

## 6. 색 맞춤
 
* 거리뷰와 ADI는 카메라, 노출, 계절, 시간대가 다름. 그대로 넣으면 같은 벽이 두 색으로 학습됨
* 정합된 자세에서 현재 scene을 렌더하고, ADI가 잘 본 영역(건물 면, 노면)에서 거리뷰 사진과 렌더의 색 차이를 비교함
* 사진별로 채널마다 곱셈과 덧셈 보정값을 맞춤. 기준은 항상 ADI 쪽 색임
* 보정 후에도 겹침 영역 색 차이가 크게 남는 사진은 폐기함

## 7. 학습

| 항목 | 값 |
|---|---|
| 넣는 곳 | 추가 시점 입력. Difix 가상 시점과 같은 형식(이름, 자세, 이미지, 마스크) |
| 손실 가중치 | 0.3에서 시작. Difix 가상 시점은 0.5를 썼음 |
| 영역별 가중 | ADI가 많이 본 면은 거리뷰 손실을 낮추고, ADI 관측이 적은 면만 높게 줌 |
| 바꾸지 않는 것 | mesh 형상과 카메라 자세. mesh-bound 2DGS는 색만 학습함 |
| 1회 학습 단위 | 블록 하나. 학습은 한 번에 하나씩 순차 실행 |

* 영역별 가중이 필요한 이유: 시기와 자세가 조금씩 다른 사진이 이미 잘 나온 영역을 흐리게 만드는 것을 막기 위함
* 가중치는 ADI 관측 횟수로 정함. 면마다 ADI 카메라에 보인 횟수가 적을수록 거리뷰 비중을 높임

#### 용도

| 용도 | 지금 방식 | 거리뷰로 바뀌는 점 |
|---|---|---|
| 미관측 면 채움 | Stable Diffusion XL Inpainting과 정밀도로지도 prior. 차량 뒤 먼 차로는 지도 격자의 약 24%가 무관측 | 실제 사진 색으로 채움 |
| V-World 건물 상층 | 관측 없음 | 위쪽 tilt 사진으로 채움 |
| Difix, ArtiFixer 참조 사진 | ADI 사진만 참조 | 궤적 밖 시점 근처의 거리뷰를 참조 뷰로 넣음 |
| LiDAR 없는 테헤란로 구간 | 형상은 지도, 색은 ADI만 | 색 관측이 늘어남. 정합 정확도가 낮을 것으로 예상함 |

## 8. 평가

| 지표 | 내용 | 통과 기준 |
|---|---|---|
| ADI holdout PSNR | 원래 학습에서 뺀 ADI 사진 | 블록 80에서 18.70보다 떨어지지 않음 |
| 거리뷰 시험 PSNR | 파노라마 5개 중 1개를 학습에서 뺌 | 거리뷰를 넣기 전 scene보다 올라감 |
| Genesis 주행 화면 | 기존 추적 카메라 영상 | 눈으로 비교. 얼룩, 이중상 여부 |
| 정합 통계 | 합격 비율, 재투영 오차 분포 | 합격 비율 70% 이상이면 경로 전체로 확대 |

* 거리뷰 시험 PSNR은 처음으로 궤적 밖 품질을 정답 사진으로 재는 지표임. 지금까지 궤적 밖 품질은 눈으로만 봤음
* 거리뷰 시험 사진도 색 맞춤을 거친 뒤 비교함. 색 차이만으로 점수가 갈리지 않게 하기 위함
